## 已确认的错误与证据

| 对照 | RGB 平均值（0–255） | 与原图的平均绝对误差 |
| --- | --- | --- |
| Apex 原始导出底色 PNG | 50.684 / 40.514 / 40.389 | 基准 |
| 1.0.10 的底色 DDS | 108.332 / 100.405 / 100.235 | 57.648 / 59.891 / 59.846 |
| 本次重建底色 DDS | 50.702 / 40.515 / 40.344 | 0.075 / 0.067 / 0.087 |

原始 PNG 带 `sRGB` 和 `gamma=0.45455` 元数据。旧流程用 Pillow 处理后保存中间 PNG，丢失该标记；texconv 只指定 `BC7_UNORM_SRGB` 输出，没有声明输入也是 sRGB。结果是已编码的颜色又被当成线性值编码了一次。把原图数值再做一次线性→sRGB 转换后，与旧 DDS 的误差只有 0.054 / 0.139 / 0.064，支持这个具体诊断，见 `evidence/gamma-proof.json`。

因此“DDS 文件头已经是 BC7 sRGB”并不代表实际像素正确。新流程明确对 col/spc 使用 `-srgb`（输入和输出都为 sRGB），数据贴图使用 `--ignore-srgb`，并在打包前解码 DDS 与输入逐通道比较。法线只比较 BC5 存储的 R/G 通道，不把由着色器重建的 B 通道当作压缩错误。

## 文件格式和工具

| 语义 | DDS 格式 | DXGI | 颜色处理 |
| --- | --- | --- | --- |
| col / spc | BC7_UNORM_SRGB | 99 | `-srgb`，保留原编码 RGB；col alpha 固定为 255 |
| nml | BC5_UNORM | 83 | 线性数据，不做 gamma，不重算法线 |
| gls | BC4_UNORM | 80 | 线性单通道，不额外压暗 |
| ao / cav | BC7_UNORM | 98 | 线性数据 |

当前包没有新增 msk/opa；不能以“其他都 sRGB”套用 AO、cavity 等数据贴图。保留原始分辨率：AO 为 1024²、11 级 mipmap，其余五张为 2048²、12 级 mipmap。材质槽位保持 TF2 结构：0 col、1 nml、2 gls、3 spc、11 ao、12 cav。不能直接照搬 Apex 原材质的 5/6 槽位。

已下载并装入包内：texconv 2026.5.8.1（官方 may2026）、RePak 1.4.0、RSX 2.2.1、Python 3.13.7 嵌入式运行时、Pillow 12.3.0。`tools-manifest.json` 记录来源和哈希；新工具发布时需重新核实版本，不假定 RePak 已经是 2.0。

参考来源：

- [DirectXTex texconv 参数](https://github.com/microsoft/DirectXTex/wiki/Texconv)：输入/输出颜色空间、DDS 编码；离线副本在 references。
- [Northstar 材质文档](https://docs.northstar.tf/Modding/repak/assets/material/)：JSON/UBER 和 TF2 纹理槽位。
- [RePak 发布](https://github.com/r-ex/RePak/releases/tag/1.4.0)、[RSX 发布](https://github.com/r-ex/rsx/releases/tag/2.2.1)。
