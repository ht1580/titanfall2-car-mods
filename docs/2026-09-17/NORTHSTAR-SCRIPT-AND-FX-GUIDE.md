# Northstar 武器脚本、动画、特效与 RUI 规范

这份规范是 TitanfallModWorkbench 1.4.0 的实现依据，供后续武器移植直接复用。

## 1. 脚本只承担必须的运行时逻辑

- `mod.json` 的 `Scripts` 项必须同时声明 `Path` 与 `RunOn`；客户端视觉逻辑放 `CLIENT`，服务端规则逻辑放 `SERVER`，共享注册才使用 `UI` 或对应上下文。
- `LoadPriority` 保持 `0`。优先级不解决同路径覆盖，因此武器 keyvalues 只写模型、附件、RUI 和特效确实需要的键，不重复声明伤害、后坐力、弹药或其他模组变量。
- 每个回调先核对注册位置、VM 上下文和生命周期。粒子句柄必须来自已预缓存且在 manifest 中登记的资源；禁止直接使用未验证的负数或跨包索引。
- 能由 MDL 序列、骨骼或 VMT 完成的动画，不额外注入 Gnut。这样可以减少主菜单初始化崩溃和与其他脚本模组的冲突面。

## 2. 模型动画分层

- 固定结构绑定稳定的父骨骼；视角、机瞄和准星不绑定会随射击抽动的枪机骨骼。
- 眼睛、翅膀、转环等独立部件必须拥有独立骨骼、正确权重和与枪身一致的装配坐标，再以 `autoplay` 序列循环。
- `autoplay` 序列追加必须幂等：相同名称已存在时不重复写入。第一人称和第三人称分别核对序列、骨骼和动画帧。
- 发光覆盖层从 ILM 或遮罩筛选三角面，保留原 UV、骨骼编号和顶点权重；只沿法线做极小偏移，避免漂浮、闪烁和穿模。

## 3. 材质与特效边界

- `nml` 使用 BC5，`gls` 使用 BC4，颜色/高光/遮罩/透明图根据语义使用 BC7；颜色贴图明确 sRGB，数据贴图保持线性。
- 材质发光用独立覆盖层和安全的 VMT proxy（`Sine`、`TextureScroll`）。禁止引用 `_rt_Camera`，避免污染地图或菜单图层。
- VMT 发光只能提供材质动态。需要空间粒子时必须制作 PCF、登记完整粒子 manifest、预缓存并在正确挂点启动；没有 PCF 不能标为粒子特效。
- RPAK 材质继续使用 RePak 1.2 兼容链。VMT 覆盖层不需要为了形式再建立一个 RPAK。

## 4. RUI 处理

- 第一人称武器内嵌 RUI 应从正常参考 MDL 提取并按骨骼名称映射到重建模型，不能照搬骨骼编号。
- 弹药显示与击杀计数器是不同数据源；分别核对拓扑、UV、朝向、父骨骼和配置绑定。
- 固定 RUI 优先绑定 `def_c_base` 一类稳定骨骼；需要随动的 RUI 才绑定对应移动部件。
- bodygroup 数量或 RUI 记录数量通过，只说明结构存在，不能证明数字内容、朝向和遮挡正确。

## 5. 自动化与交付门槛

`animated-fx-recipe-template.json` 可依次执行 ILM 覆盖层、动态 VMT、`autoplay` 序列、RUI 固化、模组审计和预览卡生成。命令：

```powershell
TitanfallModWorkbench.exe --run-fx-recipe D:\mods\weapon-fx.json
```

静态审计检查：`mod.json` 脚本声明、括号结构、粒子预缓存风险、PCF manifest、`_rt_Camera`、预期序列和最低 RUI 数量。报告通过仍不等于游戏验收；最终位置、RUI 数字、透明度、声音和动画必须由实际游戏观察。
